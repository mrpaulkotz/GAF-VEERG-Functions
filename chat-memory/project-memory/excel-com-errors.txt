# Excel COM errors & gotchas

- COM SILENT NO-OP on named-function `.RefersTo=`: setting `Name.RefersTo` (or `Names.Add`) for certain AFE LAMBDA formulas REPORTS SUCCESS (no error, `$Error` empty) but the stored value is UNCHANGED — verified re-read after set still shows the old formula. Seen on enterprise `Fertiliser_InputFunctions.Fertiliser_SumProductApplied` (IFERROR/SUMPRODUCT body) and `Fertiliser_SourceData.Fertiliser_FracGASF_Source`. NOT a protection issue (ProtectStructure/Windows/ReadOnly/HasPassword all False; a trivial `Names.Add('zzz','=1')` succeeded in the same session). WORKAROUND that WORKS: manual Name-Manager delete + re-save the Excel Labs module in the UI (re-publishes). Do NOT trust COM assignment success for named-function republish — always re-read and compare; if unchanged, fall back to manual. `Invoke-AfeNamedFunctionRepublish` in scripts/afe-named-functions.ps1 detects these as persistent mismatches.
- In formula rewrite scripts, DryRun may pass while real writes fail with 0x800A03EC on specific cells.
- Use per-cell try/catch and continue; log sheet+address for rejected formulas.
- Prefer Formula2 first, then fallback to Formula for compatibility.

- `Sync-CommonSheetsAcrossWorkbooks` can throw `RPC_E_DISCONNECTED` during workbook cleanup; use safe COM cleanup and re-fetch source sheets by name instead of holding long-lived worksheet COM proxies.
- `build.ps1` already runs `Sync-CommonSheetsAcrossWorkbooks`; if passed as a trailing command, treat it as a no-op instead of invoking it again.

- In `expand-veerg-lambda-references.ps1`, avoid `GetValue(0,0)` on array-typed `Value2` for SourceData/Utility display paths; serialize the full 1D/2D array so values are not truncated to the first element.

- Direct SourceData calls that return dynamic arrays (for example, `=Common_SourceData_FracLEACH_Data`) may expose only the anchor cell via `Cell.Value2`; check `Cell.HasSpill` and read `Cell.SpillingToRange.Value2` to capture all values.

- In PowerShell functions that return Excel COM Range objects, use `return ,$range` to avoid pipeline unrolling into per-cell objects (which shows up as bogus `Rows.Count`/`Columns.Count` like 105x105 for a 5x21 table).

- `build-input-fields-json.ps1` SILENT DATA LOSS: processing many workbooks in ONE Excel COM instance degrades it; a later large workbook (e.g. aggregated Enterprise book ~14k names) opens with an incompletely-loaded Names collection and writes 0 cells/tables (no error). Fix applied: recycle Excel (`Remove-ExcelApplication`+`$excel=$null`) in the per-workbook `finally` so each opens in a fresh instance. Standalone `-WorkbookPath` always worked; only the batch failed.
- `build-input-fields-json.ps1` now also enumerates `Excel/Enterprises/` and excludes `_Template` and `*.bak`(BaseName ends `.bak`, covers `.prelink.bak.xlsx`). Enterprise module name = `Enterprise_PastureBeef` (from `Enterprise_PastureBeef_WIP_v01.xlsx`), NOT `Enterprise_BeefPasture`.
- `Resolve-ValidationList` in `build-input-fields-json.ps1` now resolves BARE-reference concatenated cascades (no SUBSTITUTE), e.g. Fuel type cell `=TRIMRANGE(INDIRECT("Table_FuelTypesPerUse["&D17&"]"))`. Prior behaviour: warned "runtime-dependent cascading list (not resolved)" + empty Options `{}`. Fix: added helpers `Get-InnerCallArg` (quote/paren-balanced INDIRECT arg extractor) + `Split-TopLevelAmpersand`, plus a branch that finds the single non-literal driver segment, resolves it via `Resolve-ParentInfo`, enumerates the parent's allowed values, and expands `<prefix><parentValue><suffix>` per branch. Options keyed by RAW parent value (no space-strip, unlike the SUBSTITUTE branch). `DependentOn` mapped to the sibling table-column field key (e.g. `FuelUse`) by intersecting the child cell with its ListObject and matching the driver cell's column. Fuel result: FuelType now has DependentOn=FuelUse + nested Options per fuel-use category. Standalone run: `-WorkbookPath .\Excel\8_Fuel_WIP_v05.xlsx`.

- `build-enterprise-excel.ps1` TEMPLATE SEEDING: enterprise config `enterprise.templateWorkbook` (per-enterprise; falls back to registry `templateWorkbook`) names a template holding the hand-designed base sheets (Home, Results, Input - Site, Input - Enterprise, Constants - Common). When set, a real build `Copy-Item`s template -> OutputPath FRESH at start, then imports all module sheets on top = full deterministic rebuild (was previously in-place: opened existing output, skipped existing sheets, so edits to the template's Input - Enterprise were NEVER used). DryRun does NOT copy; it opens the template read-only for the preview (`$basisPath = if ($DryRun -and $templatePath){$templatePath}else{$OutputPath}`, opened with ReadOnly=`[bool]$DryRun`). If no template configured, legacy in-place behaviour (output must already exist). Overview + Acknowledgements are NOT in the template but are auto-sourced from module workbooks ([common] rows), so full-rebuild does not lose them. PastureBeef: template=5 sheets -> output=35 (30 imported + Home/Constants-Common present); removed 5748 dup sheet-scoped names; 27 AFE modules merged.
- `build-enterprise-excel.ps1` sheet-scoped name DUPLICATION: copying module sheets one-at-a-time via `$srcWs.Copy(...)` makes Excel auto-create a SHEET-SCOPED copy (`'Sheet'!Name`) of every workbook-scoped name a sheet references — AFE LAMBDAs (`Module.Func`), X_Cell_*/X_Table_* ranges, etc. Enterprise book accumulated 12,168 sheet-scoped vs 1,237 wb-scoped names → Excel Labs name conflicts. DO NOT delete them via COM `Name.Delete()` in a loop: each delete re-resolves the whole dependency graph and restoring `$excel.Calculation` to automatic triggers a full multi-core recalc — 11,219 deletes pegged ~6-7 cores for 40+ min without finishing (CPU 15,900s / 40min wall, never saved). FIX: prune AFTER save, directly from `xl/workbook.xml` in the .xlsx zip via `Remove-RedundantSheetScopedNames` (near-instant). For each `<definedName localSheetId=...>` whose `name` also exists wb-scoped (no localSheetId) WITH IDENTICAL InnerText, remove the node; else keep (genuine per-sheet name). Removed exactly 11,219, kept 949 sheet-scoped (incl. 2 `_Toc*` TOC bookmarks); wb-scoped 1,237 untouched. Excel reopens the pruned file cleanly. Use XmlDocument+namespace mgr (`x`=`http://schemas.openxmlformats.org/spreadsheetml/2006/main`), PreserveWhitespace, write back via StreamWriter+UTF8(no BOM). Called post-Save/Quit, before `Merge-AfeModules`.
- `build-enterprise-excel.ps1` TEMPLATE-AUTHORITATIVE name pruning (refinement of the DUPLICATION fix): identical-RefersTo-only was TOO conservative. A copied source sheet drags in a SHEET-SCOPED shadow of a template name pointing at the SOURCE's own layout (e.g. `X_Cell_Site_StartDate` sheet-scoped -> `'Input - Site'!E12` shadowing the template's wb-scoped `'Input - Enterprise'!E12`); sheet-scoped wins resolution -> imported formulas hit the WRONG cell (user "broken name" report). FIX: `Get-WorkbookScopedNameSet -Path $templatePath` captures template wb-scoped names BEFORE import (case-insensitive HashSet), passed to `Remove-RedundantSheetScopedNames -AuthoritativeNames`. Removal rule now: drop sheet-scoped if (a) InnerText IDENTICAL to wb counterpart, OR (b) name in AuthoritativeNames AND a wb counterpart exists (template wins even if InnerText differs). Non-template differing names still KEPT — protects `X_*_PastureBeef_*` where wb-scoped is `#REF!` and the sheet-scoped copy is the ONLY valid one, plus per-sheet tables `M1_Table_*`/`M2_Table_*` and `_Toc*`. PastureBeef: removed 6648 (was 5748), kept 65 (was 969); `X_Cell_Site_*` now single wb-scoped; opens clean (35 sheets, names 2606->1697).
- `build-enterprise-excel.ps1` AUTHORITATIVE-SET must EXCLUDE broken (#REF!) template names: `Get-WorkbookScopedNameSet` originally added EVERY wb-scoped name. The PastureBeef template (`Enterprise_PastureBeef_Template_WIP_v01.xlsx`) itself contains wb-scoped `X_Cell_PastureBeef_*`/`X_Table_PastureBeef_*` as `#REF!` placeholders (leftover from deleted sheets). Those got captured as "authoritative", so the prune's template-wins rule deleted EVERY sheet-scoped `X_*_PastureBeef` copy on BOTH input sheets ('Input - Pasture Beef' + renamed 'Input - Pasture Beef (Enteric)'), leaving only wb-scoped #REF! → user report "no named ranges in the input sheets". FIX: in `Get-WorkbookScopedNameSet` skip names whose `InnerText` is empty/whitespace or matches `#REF!` (`if ([string]::IsNullOrWhiteSpace($rt) -or $rt -match '#REF!'){continue}`). A broken placeholder is not canonical so must not be authoritative; then the prune's non-authoritative rule (keep when sheet InnerText differs from wb) preserves the valid per-input-sheet copies. Context: two modules (Enteric_BeefPasture + ManureManagement_BeefPasture) both ship an 'Input - Pasture Beef' sheet with identical wb-scoped X_*_PastureBeef names but DIFFERENT cell layouts; enterprise renames one to '(Enteric)'; each input sheet keeps its own correctly-pointing sheet-scoped copy after import → both MUST survive. After fix: kept 65→258, both input sheets have all 17 X_*_PastureBeef pointing to their own cells. (Separate KNOWN-remaining issue: localise-strip binds the Enteric calc sheet's X_*_PastureBeef shadow to 'Input - Pasture Beef' instead of '(Enteric)' when two sheets share the base name — not yet fixed, lower priority.)
- `build-enterprise-excel.ps1` STALE CACHED ERROR after prune: after removing a sheet-scoped shadow, cells referencing that name still show `#VALUE!`/`#REF!` on open (re-entering the same formula fixes one cell) because Excel loads CACHED cell values and won't recalc. FIX (in `Remove-RedundantSheetScopedNames`, same workbook.xml zip edit): set `<calcPr fullCalcOnLoad="1">` (create the element after `definedNames` if absent) so Excel forces a full recalc on open, replacing cached errors. Rewrite workbook.xml if `$removed -gt 0 -OR $calcChanged`. Did NOT delete `xl/calcChain.xml` — partial delete (leaving its rel + content-type) can trigger Excel "repaired records" warning; fullCalcOnLoad alone suffices. Verified output has `<calcPr calcId=... fullCalcOnLoad="1" />`.
- `_ModuleRegistry.json` `sourceWorkbook` is now a VERSION-AGNOSTIC PREFIX (e.g. `4_2_ManureManagement_BeefPasture`, no `_WIP_v<NN>.xlsx`). `Resolve-SourceWorkbook` (build-enterprise-excel.ps1 ~line 38): exact filename match first (backward compat), else stem = hint minus ext and trailing `_v<NN>`, then match regex `^<stem>(_.*)?_v<digits>$` (the optional group allows the `_WIP` segment; trailing `_` separator prevents partial-word collisions), pick highest `_v(NN)`. Excludes `~$*`, `_expanded`, and `*.bak` (so `.prelink.bak.xlsx` ignored). Effect: workbook re-versioning no longer needs registry edits (e.g. `8_Fuel`->v05, `6_AgriculturalResidue`->v03 auto-resolve). NOTE: separate pre-existing issue — AgResidue v03 restructured its leaching sheets, so the registry's `6.3.1.1-2 Leaching and runoff` calc sheet may be missing → `DISP_E_BADINDEX (0x8002000B)` at `$srcWb.Worksheets.Item($entry.OriginalName)`; fix that sheet list separately.

- ENTERPRISE AUTO-DISCOVERY: `build-enterprise-excel.ps1` and `build-enterprise-testinput-json.ps1` now auto-build EVERY `Enterprises/Enterprise_*.json` when neither `-ConfigPath` nor `-EnterpriseId` is given (re-invoke self via `& $PSCommandPath -ConfigPath ... -DryRun:$DryRun`, then `return`). npm `build-enterprise*` scripts no longer pass `-ConfigPath` (build all). `_ModuleRegistry.json` is excluded by the `Enterprise_*.json` filter.
- STRICTMODE EMPTY-COLLECTION GOTCHA: under `Set-StrictMode -Latest`, member-enumeration `.Name` on an EMPTY property collection throws `PropertyNotFoundStrict` ("The property 'Name' cannot be found"). Hit in build-enterprise-testinput-json.ps1 when a config had `commonSheetProviders: {}` (empty) — PastureBeef's was non-empty so it never surfaced. FIX: enumerate via pipeline `@($obj.PSObject.Properties | ForEach-Object { $_.Name })` (or `foreach ($p in $obj.PSObject.Properties)`), never `$obj.PSObject.Properties.Name` directly on a possibly-empty object.

- ORPHANED EXCEL PROCESSES exhaust COM: `New-Object -ComObject Excel.Application` failing with `NoCOMClassIdentified` + `CategoryInfo: ResourceUnavailable ([New-Object], COMException)` is NOT a missing Office install — it means too many leaked headless EXCEL.EXE COM servers (seen ~100 accumulated over a day) have exhausted the COM subsystem. FIX: `Get-Process EXCEL | Where-Object { $_.MainWindowHandle -eq 0 } | Stop-Process -Force` (kills only headless COM servers, preserves any process with a visible window / user-open workbook), then re-run. Note: even a clean build (exit 0) can leave ~13 lingering EXCEL.EXE (COM Quit() doesn't always terminate the process when refs linger), so these creep back up over repeated runs — periodic cleanup needed.

- STRINGIFIED FORMULAS in enterprise templates: cells authored as `'=...` (leading apostrophe) are stored by Excel as TEXT (`Value2`=literal "=..." string, `HasFormula`=false, PrefixCharacter="'"). `build-enterprise-excel.ps1` `Convert-StringifiedFormula` (called first in the non-DryRun localise block, before ref localisation) scans each worksheet `UsedRange.Value2`, and for string cells starting with `=` that are NOT already formulas, rewrites via `Formula2` to make them real formulas. Runs before localise so external refs they carry get rebound. Real formula cells are safe (Value2=result not "=" text, plus HasFormula guard).

- CRITICAL: When rewriting formulas that contain spilling structured refs like `Table[Col]`, read AND write via `Range.Formula2`, NOT legacy `Range.Formula`. Writing `=Table[Col]` through `.Formula` forces implicit intersection `@` (becomes `Table[@[Col]]`), which returns `#VALUE!` when the cell's row does not intersect the table's row range. This caused ~76 Fertiliser `#VALUE!` errors in build-enterprise-excel.ps1 (localise/strip + repoint passes). Fix: `$f = $ur.Formula2` and `$cell.Formula2 = $new`. Function-arg refs like `Func(Table[Col])` do NOT get `@` inserted (survive `.Formula`); only bare-cell spilling refs break. Reading `.Formula` on a stored dynamic-array formula also returns the `@`-inserted legacy form, so read Formula2 too.
