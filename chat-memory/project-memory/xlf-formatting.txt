# .xlf formatting & build pipeline notes

- .xlf files should use spaces for indentation; avoid tabs.
- Keep LatexEquation strings with single backslashes (e.g., \times, \rho), not escaped double backslashes.
- Prefer VEERG template blocks with Function + Title/Variable/Unit/Source/NIRReference/LatexEquation/Arguments.
- Excel population CLI: run `npm run populate:excel` to parse all .xlf files into Excel/GAF2-Template-Populated.xlsx (sheets Parsed_Equations, Parsed_SourceData, Parsed_Summary).
- SourceData JSON build: `npm run build:source-data` (scripts/build-source-data-json.ps1) parses source-data/SourceData_*.xlf into generated-sourcedata/<basename>.sourcedata.json at repo root. Also runs from build.ps1. -DryRun supported.
- Matrix parsing must be quote-aware: commas/semicolons appear INSIDE quoted strings (e.g. "Feed adjustment (MCjk=1,3,6)"). First matrix row = header. Scalar _Data like =LAMBDA(0.08) are not tables; skip.
- Dimension mismatches vs MAKEARRAY(<rows>,<cols>) are non-fatal warnings (e.g. SourceData_Poultry_Liveweights declares 9x3 but is actually 5x2 — real source bug).
- PowerShell 5.1 quirk: wrapping a List[object] that contains IDictionary/[ordered] items in @() throws "Argument types do not match" (inside [ordered]@{} literals AND standalone). Assign the List directly or use .ToArray()/.Count instead of @($list).
- PS 5.1 ConvertTo-Json escapes < > & ' as \uXXXX; post-replace to restore for readable JSON (headers contain "Bull < 1").
- InputFields JSON build: scripts/build-input-fields-json.ps1 uses Excel COM to extract InputCells (defined names ^X_Cell_) and InputTables (ListObjects ^X_Table_/^Table_Input) from Excel/*.xlsx into InputFields/<Module>_InputFields.json. Merges InputFields/_overrides/<Module>.json if present. BOM-free output.
- Excel COM gotcha: Worksheet.Evaluate("Table_Name[Column]") does NOT resolve structured table refs (esp. cross-sheet). Instead find the ListObject by name across worksheets, then read ListColumns.Item(col).DataBodyRange.Value2 directly (see Get-ListObjectColumnValues / Resolve-StructuredOrEvaluated). INDIRECT("Table[Col]") in data validation Formula1 must be resolved this way.
- Header parentheticals: "(select)/(dropdown)/(list)" are control-type markers, NOT units — exclude them in Get-UnitFromHeader.
- Data-validation list resolution (Resolve-ValidationList) classes: (1) cascade-by-parent = INDIRECT($Parent...) — cascade regex relaxed to accept named-cell parents WITHOUT $ (terminator lookahead (?=[),]) still excludes UNIQUE(/TRIMRANGE() wrappers); nested Options keyed by parent value. (2) static INDIRECT to a quoted constant, possibly wrapped (UNIQUE()/TRIMRANGE()) and NO '&' — extract the FIRST quoted "..." literal and resolve via Resolve-StructuredOrEvaluated. (3) RESOLVED concat cascade INDIRECT("Table_" & SUBSTITUTE($Parent," ","") & "[Col]") — extract parent via SUBSTITUTE regex + prefix/suffix literals around it; Resolve-ParentInfo follows single-cell passthrough formulas (8-hop guard) to the ultimate source defined name for DependentOn; enumerate parent values via Resolve-ValidationList on the parent source cell (NOT Get-AllowedValuesFromCell, which can't resolve INDIRECT-structured parent lists); for each parent value build <prefix><space-stripped-value><suffix> and resolve via Resolve-StructuredOrEvaluated => nested Options keyed by space-stripped parent value. (4) literal "A, B, C" or single "A". (5) range/named ref.
- Cascading dropdown output: cell gets DependentOn = parent X_Cell name; Options is a NESTED map keyed by SPACE-STRIPPED parent value. A branch that resolves to nothing OR ONLY to a literal n/a placeholder (regex (?i)^\s*n/?a\s*$, filter via Where-Object) collapses to the BARE STRING "n/a", not {"n/a":"n/a"}. Example: X_Cell_PastureBeef_ProductionRegion depends on X_Cell_Site_State (a passthrough to 'Input - Site'!$E$21 whose own validation is INDIRECT("Table_AustralianStates[Common Name]")); Queensland/WesternAustralia/NorthernTerritory get nested region options, other states get bare "n/a".
- Serialization: InputCells/InputTables MUST always be JSON arrays. A PS function returning an empty List unrolls to $null => [ordered]@{key=$null} renders as {} in ConvertTo-Json; a single-element list unrolls to a scalar => renders as a bare object. FIX: wrap the call site in @(...) e.g. $inputCells = @(Get-InputCells ...) so 0/1/N all serialize as arrays. (@(functionCall) is safe; only @($actualListOfOrderedDicts) triggers the "Argument types do not match" quirk.)
- Table[#Headers] special structured item lists the column header names — read lo.HeaderRowRange (handle '#Headers' in Get-ListObjectColumnValues).
- Excel error cells surface via Value2 as CVErr integers in band [-2146826288, -2146826245] (#NULL!..#N/A; #REF! = -2146826265). Filter that numeric band so error codes never leak into option lists.
- Excel COM instability: the Excel.Application server can crash/disconnect after processing several workbooks ($excel becomes null, every open then fails with "You cannot call a method on a null-valued expression"). Recover by recreating the app on open failure and retrying once (New-ExcelApplication/Remove-ExcelApplication). Open with UpdateLinks=0 and AskToUpdateLinks=$false.
- StrictMode + PS function returning List[string]: an EMPTY returned list is unrolled to $null, and $null.Count throws "property 'Count' cannot be found". Wrap every consumption in @(...) (safe for string lists) so empty -> Count 0.
- InputTables also includes X_Table_* DEFINED NAMES (named ranges), not just ListObjects (Get-NamedRangeTables). These are position-based matrix tables: row 1 = header row (always present per VEERG convention, cells may be empty); a column-1 mostly-text label column => ColsToRows, else RowsToCols. Population depends on row/col POSITION, not header/label strings. Never drop a field for a blank header — use positional fallback keys RowN/ColN and emit explicit Row/Col (1-based within range) + Label(ColsToRows)/Header(RowsToCols) metadata. A _Method2 segment in the table name => whole table CanOverWriteFormula. Single-row ranges (header only, no data) => non-fatal "too small to describe" warning + skip. The Cols/Rows container key is a GENERIC literal ('Column' for ColsToRows, 'Row' for RowsToCols), NOT a value taken from an Excel cell — applies to BOTH named-range and ListObject tables.
- ColumnNames is an ORDERED OBJECT (machineKey -> raw display label), NOT an array, for BOTH orientations. Machine keys come from Get-FieldKeyFromHeader. NB: the workbook has NO separate machine-key identifier for the livestock-class axis (only display headers like "Bulls < 1 year" + positional names X_Table_..._Col_NN); the source tables reuse the same display text. So keys are DERIVED from the header with semantics preserved: Get-FieldKeyFromHeader maps '<'->'Under', '>'->'Over', digit-hyphen-digit -> 'To' BEFORE PascalCasing (so "Bulls < 1 year"->BullsUnder1Year, "Bulls > 1 year"->BullsOver1Year don't collide; "Cows 1-2 years"->Cows1To2Years). For RowsToCols ColumnNames keys EXACTLY match the Rows.Row.* field keys (built from $fieldDefs, value = stored 'Header'). For ColsToRows the class axis = header row columns 2..C; the leading row-label/header column (col 1, e.g. "Method 1 default values (do not edit)") is EXCLUDED from ColumnNames AND from NumberOfCols (so 11 raw cols -> NumberOfCols 10). Cols.Column still carries the period/season axis (Spring/Summer/Autumn/Winter or January2024..). All ColsToRows tables in the repo are X_Table_* named ranges (no ListObject is ColsToRows).
- create-test-excel-from-json.ps1 has a -Context param (Test|Emissions, default Test). Test => overwrite ALL targeted cells incl protected formula cells ($overwriteAllFormulas=$true); Emissions => respect CanOverWriteFormula (mirrors conversational-input consumer). Wire is `$allowFormulaOverwrite = $overwriteAllFormulas -or (Test-AllowFormulaOverwrite...)` at THREE Set-CellValueIfWritable call sites (named cell ~1046, table field ~1237, table field-any ~1328). The enforcement gate is Set-CellValueIfWritable (skips when cell HasFormula and -not AllowFormulaOverwrite). npm run create-test-excel passes args through, so `-- -Context Emissions` works. The InputFields JSON itself (built by build-input-fields-json.ps1) is unchanged; the emissions rule lives in the external consumer + this test script.
- Get-NamedRangeTables is called at the end of Get-InputTables and de-dupes against ListObjects already seen via $seenTables. Build-NameIndex function header must sit between Get-NamedRangeTables's closing brace and its `$index = @{}` body — easy to accidentally delete when inserting functions there.
